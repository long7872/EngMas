# EngMas - Mobile Learning Platform

> **An intuitive, modern Android application for interactive English learning, vocabulary mastering, and real-time challenges.**

EngMas is a portfolio-grade English learning client built entirely with Kotlin. It combines structured learning paths, practice utilities, social competition, voice practice, and AI-assisted conversation in a responsive Jetpack Compose experience. The app consumes the [EngMasServer](https://github.com/long7872/EngMasServer) REST API and integrates Firebase-backed identity and challenge data.

## Key Features & Highlights

- **Interactive learning modules** - Vocabulary discovery, grammar lessons, flashcards, courses, exams, review flows, and voice-practice activities are organized into focused learning journeys.
- **Gamification that encourages consistency** - Study streaks, weekly statistics, score tracking, badges, competitive challenges, and ranked leaderboards turn practice into measurable progress.
- **Real-time challenge experience** - Online challenge rooms use Socket.IO events for connection state, room participation, and live synchronization, while Firebase-backed challenge data supports durable scoring and user records.
- **Responsive, state-driven UI** - Screen-level ViewModels expose `StateFlow` and Compose state, allowing smooth recomposition, explicit loading/error states, and non-blocking asynchronous work.
- **Offline-friendly session continuity** - DataStore preserves study timing and download state; grammar content and voice recordings use scoped device caching to reduce unnecessary work between interactions.
- **Rich platform integrations** - Firebase Authentication, Firestore, image loading with Coil, multipart voice analysis, notification/audio permissions, PDF and ZIP content handling, and Gemini/DeepSeek chatbot surfaces extend the learning experience beyond basic CRUD.

## Tech Stack & Mobile Architecture

| Area | Implementation |
|---|---|
| **Language & core** | Kotlin 2.1.10, Coroutines, `StateFlow`/`MutableStateFlow`, Compose state, and `viewModelScope` |
| **UI framework** | Jetpack Compose, Material Design 3, Compose Navigation, Material icons, window size classes, and responsive recomposition |
| **Networking & real-time** | Retrofit 2.9, Kotlin Serialization/Gson converters, OkHttp, logging interceptor, and Socket.IO client 2.0 |
| **Architecture** | Feature-oriented MVVM with repositories and unidirectional state consumption from ViewModels into composables |
| **Authentication & cloud** | Firebase Authentication, Cloud Firestore, Firebase Analytics, Google Services, and Credential Manager dependencies |
| **Persistence & caching** | Preferences DataStore for session/progress metadata; scoped `cacheDir` files for grammar and audio; Room/KSP is configured for future local database work |
| **Media & content** | Coil Compose, WAV recording, Android PDF Viewer, Zip4j, and multipart voice-analysis requests |
| **AI learning surfaces** | Gemini Generative AI client and a Retrofit-based DeepSeek chatbot implementation |
| **Build toolchain** | Android Gradle Plugin 8.7.3, Gradle Wrapper, compile/target SDK 35, and Java/Kotlin JVM target 11 |

## Project & Package Structure

```text
app/src/main/java/com/example/engmas/
 MainActivity.kt                 # App entry point, Firebase setup, runtime permissions
 audio/                          # Audio capture primitives (WAV recording)
 auth/                           # Authentication-related support code
 data/
    model/                      # API, learning, course, challenge, and user models
    repository/                 # REST/Firebase data access and error propagation
    store/                      # DataStore-backed session preferences
 network/
    EngMasApiService.kt         # Retrofit REST contract
    RetrofitClient.kt           # Base URL, converters, and OkHttp configuration
    SocketManager.kt            # Socket.IO lifecycle and event bridge
 ui/
     EngMasApp.kt                # App shell, global state, navigation integration
     GeneralViewModel.kt         # Shared study-timer state
     navigation/                 # Login-aware navigation graph
     screens/                    # Feature UI + screen ViewModels
        account/
        auth/
        challenge/               # Offline, online, and scoreboard flows
        chat/                   # Gemini and DeepSeek chatbot surfaces
        exam/
        practice/               # Courses, flashcards, grammar, vocabulary, voice
     theme/                      # Compose theme, typography, and colors
     utils/                      # UI-focused helpers
```

The structure keeps rendering, state orchestration, and data access separate: composables render state and dispatch user intent, ViewModels coordinate asynchronous work, repositories isolate backend/cloud details, and network clients centralize transport configuration.

## App Architecture & State Management Flow

The runtime flow is intentionally unidirectional:

1. **User action** is dispatched from a composable.
2. The **ViewModel** receives the intent and launches asynchronous work in `viewModelScope`.
3. A **Repository** coordinates the required source:
   - Retrofit and OkHttp for EngMasServer REST endpoints.
   - Firebase Authentication and Firestore for identity and cloud data.
   - `SocketManager` for Socket.IO connection and challenge events.
4. The ViewModel emits loading, content, error, and live-update state through `StateFlow` or Compose state.
5. The composable collects the state and performs a targeted **Compose recomposition**.

ViewModels own screen state and launch work in `viewModelScope`, so network, Firebase, file, and socket operations do not block the main thread. Repositories provide a single boundary for REST and cloud operations, while `SocketManager` exposes connection and event behavior for online challenges. Compose collects the resulting state with lifecycle-aware effects and redraws only the affected UI surfaces.

## Getting Started & Building

### Prerequisites

- Android Studio **Jellyfish or Ladybug (2023.3.1+)**
- JDK **11** (the project targets Java 11)
- Android SDK Platform **35**
- An emulator or physical device running Android **7.0 / API 24** or higher
- The Gradle Wrapper included in this repository (`gradlew` / `gradlew.bat`)

### Configuration

1. Clone the repository and open it in Android Studio.
2. Allow Gradle to sync and install the Android SDK 35 platform if prompted.
3. Confirm Firebase configuration is available at `app/google-services.json` for authentication and Firestore features. Use your own Firebase project credentials for a production deployment.
4. Configure the REST base URL in `app/src/main/java/com/example/engmas/network/RetrofitClient.kt`:

   ```kotlin
   private const val BASE_URL = "https://engmasserver.onrender.com/"
   ```

   For a locally running backend, use `http://10.0.2.2:3000/` from the Android Emulator or `http://127.0.0.1:3000/` on a device/network setup that can reach the host.

5. Configure the Socket.IO endpoint in `SocketManager.kt` to match the same environment. The current source defaults to the emulator development endpoint (`http://10.0.2.2:3000`), so update it when connecting to a deployed Socket.IO server.
6. Keep API keys and service credentials out of source control. Prefer `local.properties`, Gradle properties, or a secrets manager for local and CI builds.

### Build and install

Most development is performed in **Android Studio**:

1. Open the project root in Android Studio.
2. Wait for Gradle sync to complete.
3. Select an emulator or connected Android device from the device selector.
4. Choose the `app` run configuration and click **Run** for a debug installation.
5. To generate a distributable package, open **Build > Generate App Bundles or APKs** and select the required build variant.

The project supports both **debug** and **release** builds. Release and debug packages are generated locally and are intentionally not committed or published as GitHub release assets. This keeps generated binaries, signing material, and environment-specific configuration outside source control.

```bash
# macOS / Linux
./gradlew assembleDebug
./gradlew installDebug
./gradlew assembleRelease

# Windows PowerShell
.\gradlew.bat assembleDebug
.\gradlew.bat installDebug
.\gradlew.bat assembleRelease
```

Debug APKs are generated under `app/build/outputs/apk/debug/`, while release APKs are generated under `app/build/outputs/apk/release/`. For a signed production release, configure signing credentials through local or CI secrets rather than committing them to the repository. Run the available unit and instrumented test tasks with:

```bash
./gradlew test
./gradlew connectedAndroidTest
```

## Ecosystem Integration

EngMas is the mobile client in a two-part product ecosystem:

- **Backend repository:** [EngMasServer](https://github.com/long7872/EngMasServer)
- **Live REST API:** [engmasserver.onrender.com](https://engmasserver.onrender.com)
- **Client repository:** this Android application

The client consumes backend endpoints for users, friendships, vocabulary, topics, courses, progress, and voice analysis. Firebase complements the API for authentication, Firestore challenge documents, and score/user data, while Socket.IO provides the real-time transport for online challenge interactions.
